# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Docusaurus 3 developer-docs site for the Blue Core project. Most Markdown under `docs/` is **imported** by sync scripts from GitHub repos/wikis, Google Drive downloads, Box and code generators; guides are hand-written (often by AI agents). Next to the site run two Node services: an **MCP server** (agents search the docs and live GitHub data) and an **"Ask the docs" chat helper** that drives a local AI CLI. Plain ESM `.mjs` throughout, no TypeScript, no test suite and no linter.

## Commands

Docker (recommended):

```bash
make up        # full sync, then dev preview :3000 (hot reload) + MCP :3001 + chat helper :3002
make up SYNC=0 # same without the sync (quick restart); also works for make prod
make sync      # run every sync step in the container (docker compose run --rm --build sync)
make prod      # full sync, then nginx production build :8080 + mcp-prod :3001 + chat :3002
make mcp       # only the MCP server
make chat      # only the chat helper (runs on the host, not Docker)
make shell     # bash in the dev container
make rebuild   # rebuild images after changing package.json
make down
```

Without Docker:

```bash
npm install && npm install --prefix mcp
npm start                 # http://localhost:3000/<REPO_NAME>/ (set BASE_URL=/ for the root)
npm run build             # prebuild regenerates static/llms.txt + llms-full.txt
npm run sync              # all sources; or one step:
npm run sync:readmes      # GitHub repos, org discovery, wikis
npm run sync:drive-downloads | sync:box | sync:status | sync:code | sync:google-docs
npm run mcp               # MCP over HTTP on :3001 (`node mcp/server.mjs` alone = stdio)
npm run chat
```

In `make up`, the site hot-reloads, and the MCP server and chat helper run with `node --watch`, so code edits apply without a restart. The container keeps its own `.docusaurus/` (an anonymous volume), so host builds can't break the running dev server. Host builds still overwrite `build/`, so verify with `--out-dir` set to a scratch folder.

There are no tests. To verify a change, run `npm run build` (broken links only warn, see `onBrokenLinks`) or run the affected sync step.

## Architecture

**Content pipeline.** `docs-sources.json` is the single config for everything imported (`readmes`, `githubOrgs`, `driveDownloads`, `boxFolders`, `codeDocs`, `projectStatus`, …; `"enabled": false` skips an entry). `scripts/sync/index.mjs` runs each step in order (`syncGoogleDocs` is currently commented out). Shared helpers are in `scripts/sync/lib.mjs`: `resetDir` wipes a generated folder each run so deleted sources disappear, and `writeDoc` writes front matter (`title`, `last_update` from the *source's* modified date, `custom_edit_url` pointing back to the source). Pandoc (with the Lua filter in `scripts/sync/pandoc/`) converts `.docx`; `scripts/sync/convert/` handles Box and `.pptx`. The sidebar is fully autogenerated from the `docs/` tree (`sidebars.js`), ordered by `sidebar_position` / `_category_.json`.

**Only hand-written docs are committed.** Never hand-edit `docs/blue-core-repos/`, `docs/blue-core-wiki/`, `docs/google-drive/`, `docs/box/`, `docs/reference/` or `docs/project-status/`. They are overwritten on sync, so change the source or the sync script instead. All of these, plus `docs/design/` (hand-copied Figma notes) and everything in `imports/` except the folder layout, are git-ignored:
- **GitHub docs** are pulled on every `make up`/`make prod` and in the deploy workflow.
- **Drive, Box, Figma and the private project board** are internal and local only. The Drive and Box steps *remove* their section when the source files are missing, and `docusaurus.config.js` (`ifSection`) only adds navbar/footer links for section folders that exist. Keep both rules when adding a source: a missing source must leave no trace.
- **Drive and Box skip unchanged sources** by comparing a `.source-stamp` fingerprint (`fingerprint`/`isUpToDate` in `scripts/sync/lib.mjs`). `SYNC_FORCE=1` bypasses it, and `docker-compose.yml` passes it through.

**Markdown parsing.** `markdown.format: 'detect'`: `.md` is plain CommonMark (safe for messy imports), `.mdx` is MDX. Mermaid code blocks render as diagrams.

**Project Status pages.** `scripts/sync/project-status.mjs` writes `.mdx` pages that import React components from `src/components/ProjectStatus/` plus a JSON snapshot in `_data/`. In the browser the components then poll the MCP container's live API (`customFields.liveApiUrl`, default `http://localhost:3001/api`) and fall back to the snapshot. The GitHub fetching and CI-metric logic lives in `mcp/github.mjs` and `mcp/ci-metrics.mjs` and is **shared** by the sync script and the live API, so changes there affect both. On the public deploy the sync runs with `PUBLIC_BUILD=1`, which leaves out project boards (unless an entry has `"public": true`). The section shows as one sidebar link (`customProps.hideItems` + `sidebarItemsGenerator`), and the pages link to each other through `StatusNav.js`, driven by the generated `_data/nav.json`. Test suites come from `testSuites()` in `mcp/github.mjs` (`integrationTests` plus `repoTests`), which the sync, the live API and the `integration_tests` MCP tool all use. `parseTestLog` handles pytest, Jest, Vitest and Playwright logs. Version Drift also probes the deployed sites in `versionDrift.environments` through each service's `health` path (plain public GETs, no token). Pull Requests (`mcp/pulls.mjs`) and Version Drift (`mcp/drift.mjs`) follow the same pattern: a fetch function shared by the sync, the live API (`/api/github/pulls|drift/<org>`) and an MCP tool. `mcp/diagnose.mjs` adds the `diagnose_test_failure` tool: it gathers evidence (error blocks, changes since the last pass, flakiness, pattern hints) and leaves the reasoning to the calling agent.

**MCP server (`mcp/`).** It has its own `package.json`/`node_modules`. `server.mjs` registers the docs tools (`search_docs`, `read_doc`, `list_docs`) on top of `docs-index.mjs`, an in-memory BM25 index over `docs/` that rebuilds itself every 30s with no build step. Further tool groups come from `github-tools.mjs`, `api-tools.mjs`, `docs-health.mjs` and `prompts.mjs`. In `--http` mode the same process serves `/mcp` and `live-api.mjs`'s `/api/github/...`. That endpoint holds `GITHUB_TOKEN`, only serves boards/orgs listed in `docs-sources.json`, and checks request origins. Ports are bound to `127.0.0.1` because the docs include internal content.

**Notes (`mcp/notes*.mjs`, `src/components/Notes/`).** A folder of Markdown files that is also an Obsidian vault (`NOTES_DIR`, default `./notes`, git-ignored; Docker mounts it at `/notes`). `mcp/notes.mjs` reads and writes it (YAML front matter `tags`/`created`/`updated`/`author`, inline `#tags`, `[[links]]`, path checks, a `baseMtime` check so a save never overwrites an edit made elsewhere), and both `notes-api.mjs` (`/api/notes`, for `src/pages/notes.js`) and `notes-tools.mjs` (MCP tools) use it. Folders exist on disk (empty ones too, `listFolders`); the page can create, rename and delete empty folders and move notes (`/api/notes/folder*`, `/api/notes/move`), always keeping file names so `[[links]]` survive. Pinning is a `pinned: true` property; renaming (`/api/notes/rename`) rewrites `[[links]]` in other notes; the trash records origins in `.trash/.restore.json`; pasted images go to `attachments/`; templates are notes in `Templates/` (`saveTemplate`, `POST /api/notes/templates`, makes one from a note or text); `duplicateNote` (`/api/notes/duplicate`) copies a note. Docs pages show notes that link to them (`DocNotes`, in the `DocItem/Content` wrapper, via `/api/notes/doc-links`). Export (`POST /api/notes/export`) zips notes with `mcp/zip.mjs`, a dependency-free ZIP writer. The MCP notes tools (`notes-tools.mjs`) can return images as MCP image content (`read_note include_images`, `get_note_image`; raster only, 3 MB cap). The write tools (`create_note`, `update_note`, `duplicate_note`, `complete_task`, `rename_note`, `pin_note`, `attach_image`, `save_template`) are the MCP server's only writes; Codex needs each pre-approved in `chat/providers/codex.mjs`. Notes record which AI wrote them (`author` + exact `model`, and `edited_by`/`edited_model` for AI edits): the chat providers send `x-notes-agent`/`x-notes-model`/`x-notes-run` headers on their MCP connection, the chat helper registers the exact model behind an alias for each run (`POST /api/notes/agent-run`), and `mcp/agent-runs.mjs` (`writerOf`) resolves it for the write tools. Deleting is only on the Notes page (`POST /api/notes/delete`, exact paths only), and it moves notes to the vault's `.trash` rather than erasing them. Writes need a JSON body from an allowed origin, and `/mcp` refuses browser origins that aren't local. The navbar link only exists when `LIVE_API_URL` is set, so the public site has no notes.

**Chat helper (`chat/`).** `chat/server.mjs` runs on the host, not in Docker, because it uses the user's Claude Code / Codex logins. `scripts/with-chat.sh` starts and stops it around `make up`/`prod`. Each provider in `chat/providers/` spawns its CLI restricted to the MCP server's tools (read-only, plus the two note-writing tools, which the system prompt only allows when the user asks; Codex needs them pre-approved with `mcp_servers.docs.tools.<tool>.approval_mode`), and the question is passed on stdin. To add a CLI, add a provider file there. The UI is `src/components/AskDocs/`, mounted globally through `src/theme/Root.js`.

**Deployment shapes.** The `Dockerfile` stages are `deps` → `dev` / `build` → `prod` (nginx, `docker/nginx.conf` proxies `/api/live/` → MCP and `/api/chat/` → host chat helper) and `mcp` (bakes the `docs/` snapshot). `SITE_URL` and `BASE_URL` control the URL (Docker uses `/`, GitHub Pages uses `/<REPO_NAME>/`). `.github/workflows/deploy.yml` (on push and hourly) runs only `npm run sync:readmes` before building, with `LIVE_API_URL=''` and `CHAT_API_URL=''`, so the public site has public GitHub content only: no live data, chat or local-only sections.

`docker-compose.yml` mounts `SOURCES_DIR` (default `../..`) read-only at `/sources`, so `docs-sources.json` can reference local checkouts as `"local": "/sources/<repo>"`. It also mounts `BOX_DIR` at `/box`.

## Writing docs pages

Follow `STYLE_GUIDE.md` for any page you write or edit (front matter `title`, a short "what/why" intro, `##` sections, language-tagged code blocks, admonitions, "Related" links, prefer `.md` over `.mdx`, add `<!-- TODO: verify -->` rather than invent APIs). `AGENT_PROMPTS.md` holds the standard prompts for agent-written guides. Hand-written guides go in `docs/guides/` and `docs/getting-started/`.

Keep `includePrivate: false` in `githubOrgs` while the site is public, because `GITHUB_TOKEN` can read private repos.
